# QLDA V9.1 → V9.6 Advanced Automation

## Scope and safety contract

Every AI execution is isolated by contractor `workspace_project_id`. There is no shared contractor memory/state for operational AI actions. The existing Tool Registry remains the only AI action boundary: RBAC, data-integrity checks, approval policy and audit are not bypassed.

The following rules are intentional and permanent unless the business policy is explicitly changed:

- Digital Twin is not part of the runtime.
- `PAYMENT_OVERDUE` is not a Project Health finding. Legacy cumulative IPC amounts are not treated as overdue debt.
- A VO generated by AI is always a draft until the existing VO approval workflow is used.
- Site Vision only creates a progress proposal. It never writes `tasks.actual_progress`; the existing `update_schedule_progress` approval gate remains authoritative.
- IPC/BOQ reconciliation arithmetic is deterministic code, not LLM arithmetic.
- Predictive schedule risk is an auditable velocity extrapolation with bounded confidence, not a guaranteed completion date.

## V9.1 Autonomous Task Routing

`route_work_task` detects discipline from a verified finding, searches existing workspace documents/tasks for responsible-person evidence, assigns SLA and priority, and stores a duplicate-safe route fingerprint in `qlda_ai_task_routes`.

Supervisor runs automatically create route proposals. A route proposal is not the same as a completed work task. Creation of an actual work task remains a separate service operation.

## V9.2 Smart Contract Audit

`audit_contract_obligations` creates a contractor-scoped obligation ledger from structured contract/appendix expiry dates, relevant contractual document due dates and dated obligation notes. The persistent ledger is `qlda_contract_obligations`.

The engine reports open obligations, overdue obligations, and obligations due within 30 days. Each row keeps a source reference/evidence string so the warning can be traced back to the originating record.

## V9.3 Smart IPC ↔ BOQ Reconciliation

`reconcile_ipc_boq` compares the selected/latest IPC detail rows with BOQ rows in the same workspace. Current deterministic flags include:

- `UNMATCHED_IPC_ITEM`
- `UNIT_MISMATCH`
- `CONTRACT_QTY_MISMATCH`
- `UNIT_PRICE_MISMATCH`
- `CUMULATIVE_EXCEEDS_BOQ`
- `COMPLETION_OVER_100`
- `DUPLICATE_CLAIM_ITEM` (low-severity review flag because repeated names may represent valid areas)

Results are stored in `qlda_ipc_boq_reconciliation`. High/critical verified flags feed AI Supervisor as `IPC_BOQ_MISMATCH`.

## V9.4 Automated VO Drafting

`draft_vo_from_change` accepts structured change evidence or a scoped RFI/RFA document, looks up a BOQ rate when possible, calculates the quantity delta and stores an AI draft in `qlda_vo_drafts`.

It never writes to the official `variation_orders` workflow and never approves a VO. `approve_vo` remains critical/approval-required.

## V9.5 Predictive Project Risk

`forecast_project_risk` uses current task progress and elapsed time to calculate deterministic observed production velocity for tasks that have enough evidence. It stores snapshots in `qlda_ai_forecasts` and returns:

- forecast risk score;
- bounded confidence;
- predicted task/project finish dates when velocity exists;
- maximum predicted delay;
- task-level evidence.

For cash visibility it may total existing unpaid IPC obligations whose real `due_date` falls within 30/60 days. These values are future verified cash needs only; they are not called overdue and do not reduce Project Health through a payment alarm.

## V9.6 Site Vision Progress

`analyze_site_progress` can consume an existing image attachment stored under the current contractor workspace or a verified manual observation. OpenAI/Gemini Vision returns an observed quantity and confidence. QLDA then calculates the proposed progress percentage deterministically and stores it in `qlda_site_vision_observations`.

The proposal must be reviewed before the existing `update_schedule_progress` workflow is used.

## AI Supervisor integration

A daily/manual contractor Supervisor run now composes:

1. Data Integrity;
2. schedule/contract status;
3. NCR/RFI/inspection and Google production freshness;
4. V9.2 Contract Obligation Audit;
5. V9.3 latest IPC↔BOQ reconciliation;
6. V9.5 predictive schedule risk;
7. V9.1 task-route proposals for resulting findings.

The Supervisor schema is versioned so legacy snapshots are not rendered as current after business-rule changes.

## Admin UI

The AI Project Supervisor page contains an Admin-only `AI Automation V9.1–V9.6` expander. It provides explicit controls for Contract Audit, IPC↔BOQ reconciliation, 60-day risk forecast, Draft VO generation, Site Vision proposal and task-routing review.
