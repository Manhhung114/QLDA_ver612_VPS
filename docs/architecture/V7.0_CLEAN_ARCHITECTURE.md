# QLDA V7.0 — Clean Architecture

V7.0 completes the architectural boundary started in V6.25–V6.27 without
changing the PostgreSQL schema or business calculations.

## Dependency rule

The source dependency direction is:

```
domain <- application <- infrastructure
       <- application <- presentation
```

`domain` contains only business contracts, errors and value objects. It does not
know FastAPI, Streamlit, PostgreSQL, file storage or any V6.x compatibility
module.

`application` contains use cases and depends only on `domain` ports. It does not
import `qlda.infrastructure`, `qlda.services`, `qlda.modules`,
`qlda.shared.legacy`, FastAPI or Streamlit.

`infrastructure` implements the ports. `legacy_adapters.py` is the explicit
anti-corruption layer that delegates to the proven V6.x runtime while those
implementations are retired incrementally.

`presentation` contains FastAPI and Streamlit adapters. The V7 FastAPI routers
use `qlda.bootstrap.get_application()` and never import the V6 service layer
directly.

## Composition root

`qlda.bootstrap` is the only V7 composition root. It wires application use cases
to infrastructure adapters and caches one `ApplicationServices` instance per
process. The Excel worker uses the same composition root as FastAPI.

## Compatibility strategy

The old `qlda.services` package remains available as a deprecated compatibility
surface because the existing Streamlit application and V6 domain facades still
depend on proven code. New V7 entry points must not import it directly.

The permitted temporary path is:

```
FastAPI / Worker
      |
      v
Application use cases
      |
      v
Domain ports
      ^
      |
Infrastructure legacy adapters
      |
      v
V6 compatibility runtime
```

This lets QLDA migrate individual repositories/parsers later without changing
HTTP endpoints or worker orchestration.

## V7 invariants

- No database schema migration.
- No change to BOQ/IPC/VO/Schedule formulas or revision rules.
- No change to Excel transaction/rollback behavior.
- No change to `/api` public routes.
- Uvicorn remains a separate localhost process behind Nginx.
- Domain/application packages have no framework or legacy imports.
- V6.25, V6.26 and V6.27 regression suites remain valid.

## Next migrations inside V7.x

Future V7.x work should replace each legacy infrastructure adapter with native
repositories one bounded context at a time: jobs/files first, then project
access/search, then AI and heavy Excel domain persistence. Because the ports are
stable, those changes do not require presentation rewrites.
