# V7.4 – Native Excel Import

V7.4 completes the migration of all `ApplicationServices` ports to native V7
infrastructure adapters.

## Native Excel boundary

`src/qlda/infrastructure/native_excel.py` implements `ExcelImportPort` directly.
The composition root wires `ExcelImportUseCases(NativeExcelImportAdapter())`.
`LegacyExcelImportAdapter` and `src/qlda/infrastructure/legacy_adapters.py` are
removed from the runtime.

The native adapter owns:

- `.xlsx/.xlsm` workbook scanning;
- job type normalization, including `BOQ_IMPORT -> BOQ`;
- project/workspace validation;
- BOQ, IPC, VO and Schedule import orchestration;
- cancellation/progress propagation;
- result/verification payload compatibility.

## Preserved business invariants

V7.4 deliberately does not rewrite the proven parser/persistence engines. They
are loaded lazily through `qlda.runtime.legacy_import` from the repository root,
so the existing V6.24 database algorithms stay intact while the application
boundary becomes native.

Preserved behavior includes:

- BOQ exact `expected/scanned/prepared/written/failed` row verification;
- BOQ batch persistence, rollback/cancel semantics and saved-workbook snapshot;
- IPC independent claims, revision numbering and SHA/idempotency behavior;
- VO independent revisions and existing approved/funding/status preservation;
- Schedule background replacement rules, manual/MPP task preservation and
  `status_date` propagation;
- existing PostgreSQL transaction boundaries;
- worker progress, cancellation and result payload contracts.

## Dependency rule

`native_excel.py` may depend on infrastructure/runtime compatibility loading,
but it must not import:

- `qlda.services`;
- `qlda.modules`;
- `qlda.shared.legacy`.

Compatibility engines are lazy and are not loaded while composing the
application.

## Compatibility service layer

The old `qlda.services.boq/ipc/vo/schedule/excel` modules remain available for
older callers and regression tests. They are no longer on the V7 runtime path.
Their later removal is a separate cleanup and is not required for the V7.4
native-adapter milestone.

## Architecture state after V7.4

Native adapters:

- Session
- Project Access
- Files
- Jobs
- Search
- AI
- Excel Import

`LEGACY_ADAPTERS = ()`.

This means the V7 application composition has no remaining legacy adapter.
It does **not** yet mean every root-level V6 compatibility engine has been
rewritten; those engines remain intentionally isolated behind infrastructure.
