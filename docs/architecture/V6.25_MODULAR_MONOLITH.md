# V6.25 — Modular Monolith

V6.25 migrates QLDA from a flat set of versioned Python files toward one deployable modular monolith under `src/qlda/`.

## Goals

- Preserve all V6.24.5 business behavior and PostgreSQL data.
- Introduce stable module namespaces before moving large implementations.
- Keep one deployable application and one PostgreSQL database.
- Prevent a risky big-bang rewrite of BOQ, IPC, VO, Schedule and AI code.
- Prepare V6.26 Service Layer and V6.27 FastAPI without duplicating business logic.

## Package layout

```text
src/qlda/

├── presentation/
├── shared/
│   └── legacy.py
├── module_registry.py
├── runtime.py
└── modules/
    ├── boq/
    │   ├── background.py
    │   └── persistence.py
    ├── ipc/
    │   ├── background.py
    │   └── persistence.py
    ├── vo/
    │   ├── background.py
    │   └── persistence.py
    ├── schedule/
    │   ├── background.py
    │   └── persistence.py
    └── excel/
        ├── jobs.py
        └── worker.py
```

## Migration rule

V6.25 uses a strangler migration. New code imports stable `qlda.modules.*` namespaces; existing V6.22-V6.24 root modules remain the proven compatibility implementations until each domain is physically moved. Every bridge to those old files passes through `qlda.shared.legacy`, so legacy coupling is explicit and searchable.

Public facades now exist for:

- `qlda.modules.boq.background` / `persistence`
- `qlda.modules.ipc.background` / `persistence`
- `qlda.modules.vo.background` / `persistence`
- `qlda.modules.schedule.background` / `persistence`
- `qlda.modules.excel.jobs` / `worker`

The production Excel worker runs through the stable entrypoint:

```bash
python -m qlda.modules.excel.worker --poll-seconds 2
```

That entrypoint delegates to the proven V6.24.5 implementation today. Later V6.25/V6.26 commits can move internals without changing systemd again.

## Dependency direction

- `presentation` may call public module APIs.
- business modules may use `infrastructure` and `shared`.
- modules must not import Streamlit directly in core/package facades.
- cross-domain callers should target another module's public API, not a private implementation file.
- root versioned modules are compatibility adapters, not new extension points.
- access to root compatibility code is centralized in `qlda.shared.legacy`.

## V6.25 invariants

V6.25 intentionally does **not** change:

- PostgreSQL schema or existing project data;
- BOQ, IPC, VO or Schedule formulas/parsers;
- approval permissions and workflow states;
- file upload/storage semantics;
- batch transaction, rollback or PostgreSQL row-count verification;
- Streamlit as the primary presentation runtime.

## Definition of done

V6.25 is structurally complete when every V6.24 background domain has a stable package boundary, production processes can import `src/qlda`, legacy access is isolated behind the bridge, and architecture tests enforce those rules.

## Next step — V6.26

V6.26 introduces an explicit Service Layer inside these boundaries. It will progressively remove monkey-patch/direct-database calls from presentation code while keeping V6.25 public module paths stable.
