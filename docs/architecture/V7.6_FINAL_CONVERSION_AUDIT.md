# V7.6 – Final Conversion Audit

Status: planned from V7.5. **V7.6 is the final migration/conversion release.**
After V7.6, future releases must be feature, performance, security or maintenance
releases; they must not require another legacy-to-native conversion phase.

## 1. Audit of V7.5

V7.5 has native application ports/adapters and packaged BOQ/IPC/VO/Schedule import
engines, but the runtime is not yet fully native.

Remaining conversion blockers:

1. `src/qlda/runtime.py` still exposes `legacy_import()` and injects the repository
   root into `sys.path`.
2. `src/qlda/infrastructure/database.py` still boots `postgres_backend_v622` and
   the historical `cloud_db.CloudDatabase` compatibility API.
3. `NativeAIAdapter` still loads the root AI/context/contractor semantic stack
   through the compatibility loader.
4. Packaged BOQ/IPC/VO import engines still import root V6.22 semantic parsers and
   helpers. Packaging alone therefore does not make the parser stack independent.
5. Production Streamlit is still reconstructed at runtime from the V6.21 source
   bundle, patched by V6.22/V6.24 patch modules, compiled and executed dynamically.
6. Docker/systemd still launch the root `streamlit_app.py`; the Docker build still
   compiles/builds the historical versioned runtime.
7. A number of existing tests/workflows validate historical implementation files.
   These must be migrated to stable behavioral contracts before those files can be
   safely removed.

## 2. V7.6 final target

The production dependency rule after V7.6 is:

```text
presentation (Streamlit/FastAPI/worker)
                |
          application use cases
                |
              domain
                |
 infrastructure / repositories / integrations
                |
        PostgreSQL + VPS SSD + AI providers
```

Production code must be importable and runnable from `src/qlda` without loading
versioned root Python modules or reconstructing generated source.

## 3. Mandatory conversion work

### A. Native Streamlit presentation

- Create the canonical Streamlit application under `src/qlda/presentation/streamlit/`.
- Port the current generated application/pages/controllers into source-controlled
  modules; do not rebuild them from Base64/GZip at runtime.
- Route authentication, project/workspace access, files, jobs, AI and Excel work
  through application use cases/native modules.
- Replace root `streamlit_app.py` with a minimal native entrypoint, or point
  systemd/Docker directly at the packaged entrypoint.
- Remove runtime `exec`, dynamic source compilation and source patch chains.

### B. Native PostgreSQL database core

- Replace the `CloudDatabase` compatibility runtime with native PostgreSQL
  repositories/gateways built on the existing `qlda.infrastructure.postgres` layer.
- Remove production dependency on `postgres_backend_v622.py` and `cloud_db.py`.
- Remove `bootstrap.get_database()` compatibility escape hatch by the final V7.6
  commit.
- Preserve transaction boundaries and rollback behavior.

### C. Native BOQ / IPC / VO / Schedule semantics

Move or refactor the proven semantic code into `src/qlda` and update packaged
engines to import only packaged modules.

Required coverage includes:

- BOQ multisheet parsing, material/labor split, terminology and price recovery.
- IPC core parser, fast path, summary/adaptive/payment semantics, numbering,
  period handling and price recovery.
- VO core parser and independent revision semantics.
- Schedule Excel parser/persistence semantics.

Persistence code must stop importing root `ipc_claim_v622`, `vo_claim_v622` or
other versioned implementation modules.

### D. Native AI semantic core

- Replace `_compat()` / `legacy_import()` bootstrapping with native provider,
  context and repository components.
- Keep OpenAI/Gemini provider behavior and resilience, but package it under
  `src/qlda`.
- Build BOQ/IPC/VO/schedule/contract/legal context through native repositories.
- Implement workspace scope/access natively instead of installing contractor
  access monkey patches.
- Preserve `AIApplicationError(code, retryable, action)` and existing FastAPI
  response contracts.

### E. Native Streamlit-side business modules

The final conversion must also cover runtime modules currently installed directly
by Streamlit, including session/workspace administration, work tasks, contract
management/duration, legal documents, runtime settings, local file/storage glue,
report/schedule/IPC/VO UI integrations and MPP integration.

External Google Apps Script code may remain as an integration artifact if it is
not imported by the VPS Python runtime.

### F. Runtime retirement and cleanup

Only after the native Streamlit/DB/semantic stacks pass equivalence and regression
checks may V7.6 remove obsolete runtime inputs, including as applicable:

- `src/qlda/runtime.py`
- root `*_v622.py`, `*_v624.py` runtime modules
- `v622_*_patch.py`, `v623_*`, `v624_*` patch/bootstrap files
- `v621_webopt_source/`
- `build_v621_webopt.py`
- obsolete root `cloud_db.py` / local VPS compatibility modules
- historical implementation tests/workflows that have been replaced by stable
  contract tests.

**Deletion order is mandatory:** native replacement -> equivalence/regression CI ->
runtime switch -> dependency scan -> deletion. Do not delete the V6.21 bundle or
build inputs first; earlier CI proved they are still required by the current
Streamlit build path.

## 4. Data/API invariants that cannot regress

V7.6 must retain all established behavior, especially:

- BOQ: expected/scanned/prepared/written/failed row verification and full rollback.
- IPC: SHA/batch idempotency, independent claim revisions, approved/disbursed/
  payment-state preservation and rollback.
- VO: independent revisions plus approved amount, funding source and status.
- Schedule: replace only `schedule_excel:*` tasks; preserve manual/MPP tasks.
- Original uploaded files remain durable on VPS storage.
- Project/contractor authorization and single-session behavior.
- Existing public FastAPI paths and payload contracts.
- Submission/approval/revision workflows used by Streamlit.

## 5. V7.6 final CI gate

Add `tests/test_v760_final_conversion.py` and
`.github/workflows/v760-final-conversion-check.yml`. The final gate must verify:

1. version is exactly `7.6`, `LEGACY_ADAPTERS == ()`, and metadata declares
   `LEGACY_RUNTIME = False`;
2. `src/qlda/runtime.py` is absent and production code contains no
   `legacy_import` or repository-root `sys.path` injection;
3. production `src/qlda` code contains no imports of root versioned modules or
   patch modules;
4. native AI contains no compatibility loader/bootstrap stack;
5. import engines pass a deep AST dependency audit, not only an adapter-level
   audit;
6. database creation/repositories are PostgreSQL-native;
7. Streamlit entrypoint contains no Base64/GZip source reconstruction,
   `compile(source)` or runtime `exec`;
8. Docker and systemd run native entrypoints and do not invoke the V6.21 build;
9. V6.21 source bundle and obsolete patch runtime are absent after the runtime
   switchover;
10. FastAPI contracts remain unchanged;
11. BOQ/IPC/VO/Schedule invariants above pass regression tests;
12. critical Streamlit workflows pass smoke/contract tests: login/session,
    project/workspace selection, files, submission/approval/revision, BOQ/IPC/VO/
    Schedule import, tasks, contracts, legal and AI;
13. Docker/build/deploy checks pass on the same final commit SHA.

## 6. Definition of Done – final conversion

V7.6 is complete only when all of the following are true simultaneously:

- No production runtime dependency on root versioned Python modules.
- No dynamic source patch/build/exec pipeline.
- No legacy compatibility import loader.
- No legacy database adapter/runtime.
- Streamlit, FastAPI and Excel worker all enter through native packaged code.
- All production adapters and semantic engines are under `src/qlda`.
- Historical version labels may remain in docs/changelog only, not as required
  runtime implementation dependencies.
- All CI checks on the final `main` SHA are completed successfully.

After this point, V7.7+ must not be described as another conversion/migration
release. The architecture migration is considered closed at V7.6.
